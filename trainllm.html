How to train an LLM

Beginner · Foundations

Choose a goal and a starting point

Training an LLM teaches a neural network to predict the next token in a sequence. The starting point shapes everything that follows. Train from scratch when you have massive compute and curated data; most projects instead fine-tune an existing base model such as Llama, Mistral, or Qwen, which provides a strong general baseline at a fraction of the cost.

Decide what the model should become. Pretraining builds broad general knowledge, fine-tuning teaches a task or domain, and alignment tunes chat behavior. Each stage uses different data and objectives, but together they form a repeatable pipeline.

Pick a starting approach

  • Prompting or retrieval: use these first when the task is mostly instructions or the model needs access to changing private facts.
  • Supervised fine-tuning (SFT): useful when you need consistent formats, domain-specific language, or a repeatable task behavior.
  • Pretraining from scratch: consider only when you need a genuinely new foundation model and have substantial, licensed data, specialist expertise, and a compute budget.

Try it: choose a first experiment

Start with retrieval or tools: keep changing facts outside the model so they can be updated and cited.

Check before training: confirm the model license permits your intended use, remove secrets and personal data you do not have permission to use, and establish a baseline with prompting or retrieval. Training from scratch is rarely the first experiment to run.

Beginner · Data

Prepare high-quality data

Data quality beats quantity. Define what one example represents, document where it came from and what rights apply, then normalize and deduplicate it. For language modeling, JSON Lines (JSONL) stores one valid JSON object per line; instruction datasets often use separate fields for the prompt and response rather than one undifferentiated text field.

Keep training, validation, and final test data separate. Split by source, person, or document where appropriate—not just by randomly shuffling near-duplicate rows—so a document cannot leak across splits. The validation set helps you choose checkpoints and settings; use the test set only for a final, less biased check.

Intermediate · Pretraining

Pretrain with next-token prediction

The core objective is causal language modeling: given a sequence of tokens, predict the next token. A tokenizer turns text into tokens, which may be whole words, word pieces, or punctuation. During training, the model compares its next-token probability distribution with the known next tokens and adjusts its weights to reduce the error.

AdamW is a common optimizer. Learning rate, batch size, sequence length, warmup, and training duration depend on the model and dataset; there is no universal safe range. Gradient accumulation simulates a larger batch across smaller device batches, while gradient checkpointing trades extra computation for lower activation memory. Track both training and validation loss: if training improves while validation worsens, investigate overfitting, data leakage, and distribution mismatch.

Intermediate · Fine-tuning

Fine-tune with supervised examples

Supervised fine-tuning (SFT) teaches a base model using examples of desired behavior. Format each example with the model's expected chat template, and mask loss on prompt tokens when the goal is to train only on the answer. Use representative examples, remove conflicting or low-quality answers, and make sure the evaluation set uses the same format as production.

LoRA (Low-Rank Adaptation) freezes the base weights and learns small matrices that approximate an update to selected layers. QLoRA additionally loads a quantized base model to reduce memory use. These techniques can make fine-tuning accessible on smaller hardware, but they do not guarantee better results: compare against a baseline and watch for forgotten general abilities, memorization, and overfitting.

from peft import LoraConfig, get_peft_model

model = AutoModelForCausalLM.from_pretrained("base-model")
peft_config = LoraConfig(
    r=8,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)
model = get_peft_model(model, peft_config)

trainer = Trainer(
    model=model,
    args=TrainingArguments(
        output_dir="./finetune-checkpoint",
        per_device_train_batch_size=4,
        learning_rate=2e-5,
        num_train_epochs=3,
    ),
    train_dataset=instruction_dataset,
)
trainer.train()

LoRA rank is a tradeoff, not a quality dial. Larger rank permits a more expressive adapter and uses more trainable parameters. Choose it with validation experiments; suitable values depend on the model, task, and target layers.

Suggested starting hyperparameters

  • Start with a small, representative dataset and a short run; inspect generated outputs before scaling up.
  • Set learning rate and epochs based on model size, data size, and validation behavior rather than copying a recipe blindly.
  • Save checkpoints and compare the base model with the fine-tuned model on the same held-out prompts.

Advanced · Alignment

Align with preference data

Preference tuning uses comparisons between candidate responses to teach a model which behavior people prefer. In a common RLHF pipeline, human comparisons train a reward model, then an optimization algorithm such as PPO updates the language model. Direct preference optimization (DPO) instead trains from preferred and dispreferred response pairs without a separate reward-model training stage.

Preference labels can encode annotator assumptions and biases. Write clear rubrics, include diverse reviewers, protect reviewers from harmful material, and check for disagreement. Preference optimization is not a substitute for safety testing, policy design, or monitoring.

from transformers import DPOConfig, DPOTrainer

trainer = DPOTrainer(
    model=model,
    args=DPOConfig(
        output_dir="./dpo-checkpoint",
        per_device_train_batch_size=2,
        learning_rate=1e-5,
        num_train_epochs=3,
    ),
    train_dataset=preferences,
)
trainer.train()

Advanced · Evaluation

Evaluate and iterate

Evaluate before and after training with a fixed, held-out test set. Loss measures prediction error on the chosen tokens; perplexity is an exponentiated form of average token loss and is meaningful mainly when tokenization and evaluation data are comparable. Neither metric alone tells you whether a model follows instructions, gives correct facts, or behaves safely.

Use task-specific tests, side-by-side comparisons with the base model, and human review. Include normal cases, edge cases, refusals, and prompts that probe memorization or leakage. Record the model and dataset versions, template, decoding settings, and evaluation date so results can be reproduced. Iterate in small loops: change one factor, measure, inspect failures, and repeat.
