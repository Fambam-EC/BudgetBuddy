A practical guide

How to train an LLM

From a first fine-tune to a fully custom model, this guide walks through training a large language model: the goal, the data, pretraining, fine-tuning, alignment, and evaluation.

1. Choose a goal 2. Prepare data 3. Pretrain 4. Fine-tune 5. Align 6. Evaluate
1

Beginner · Foundations

Choose a goal and a starting point

Training an LLM teaches a neural network to predict the next token in a sequence. The starting point shapes everything that follows. Train from scratch when you have massive compute and curated data; most projects instead fine-tune an existing base model such as Llama, Mistral, or Qwen, which provides a strong general baseline at a fraction of the cost.

Decide what the model should become. Pretraining builds broad general knowledge, fine-tuning teaches a task or domain, and alignment tunes chat behavior. Each stage uses different data and objectives, but together they form a repeatable pipeline.

Start from a base model. Training from scratch requires hundreds of billions of tokens and thousands of GPUs. Fine-tuning a strong base model is the practical starting point for almost any custom model.

Beginner · Data

Prepare high-quality data

Data quality beats quantity. Curate a small, clean, and deduplicated dataset, format it as JSONL with a text field, and split it into training and validation sets. Remove near-duplicates, filter low-quality samples, and keep a held-out set for evaluation.

{"text": "The mitochondria is the powerhouse of the cell."}
{"text": "Language models learn by predicting the next token in a sequence."}

Quality over quantity: a carefully curated set of thousands of examples can outperform a million scraped duplicates after cleaning.

Intermediate · Pretraining

Pretrain with next-token prediction

The core objective is causal language modeling: given a sequence of tokens, predict the next token. Training uses the AdamW optimizer with learning rates around 1e-4 to 3e-5, gradient checkpointing, and periodic evaluation of perplexity. A full pretraining run is compute-heavy and usually runs on cloud GPU clusters.

from transformers import AutoModelForCausalLM, Trainer, TrainingArguments

trainer = Trainer(
    model=AutoModelForCausalLM.from_pretrained("base-model"),
    args=TrainingArguments(
        output_dir="./pretrain-checkpoint",
        per_device_train_batch_size=4,
        gradient_accumulation_steps=8,
        learning_rate=3e-4,
        num_train_epochs=1,
        logging_steps=10,
        evaluation_strategy="steps",
        eval_steps=1000,
    ),
    train_dataset=tokenized_dataset,

trainer.train()

Watch the validation loss. Training loss can look fine while the model fails to generalize; validation perplexity is the first signal that training is actually working.

Intermediate · Fine-tuning

Fine-tune with supervised examples

Supervised fine-tuning teaches a base model to follow examples. Collect instruction and response pairs, format them into token sequences, and fine-tune with the Hugging Face Trainer. Small parameter-efficient methods such as LoRA or QLoRA train a small adapter on top of the base model instead of updating all weights, which greatly reduces cost and memory.

from peft import LoraConfig, get_peft_model

model = AutoModelForCausalLM.from_pretrained("base-model")
peft_config = LoraConfig(
    r=8,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)
model = get_peft_model(model, peft_config)

trainer = Trainer(
    model=model,
    args=TrainingArguments(
        output_dir="./finetune-checkpoint",
        per_device_train_batch_size=4,
        learning_rate=2e-5,
        num_train_epochs=3,
    ),
    train_dataset=instruction_dataset,
)
trainer.train()

LoRA with a rank of 8 and dropout around 0.05 is a common starting point; verify whether full fine-tuning is needed for your task.

Suggested starting hyperparameters

  • Fine-tuning learning rate: around 2e-5.
  • Training epochs: 2 to 3 over the instruction dataset.
  • Batch size: as large as memory allows, with gradient accumulation if needed.
5

Advanced · Alignment

Align with preference data

Alignment makes a chat model helpful and safe. Reinforcement learning from human feedback (RLHF) trains a reward model from human preference comparisons, then optimizes the policy with PPO. Direct preference optimization (DPO) skips the reward model and directly optimizes preference pairs, which is simpler and more stable.

from transformers import DPOConfig, DPOTrainer

trainer = DPOTrainer(
    model=model,
    args=DPOConfig(
        output_dir="./dpo-checkpoint",
        per_device_train_batch_size=2,
        learning_rate=1e-5,
        num_train_epochs=3,
    ),
    train_dataset=preferences,
)
trainer.train()

Start with a small preference set of a few thousand pairs; adding more preference data usually helps less than expected.

6

Advanced · Evaluation

Evaluate and iterate

Evaluate before and after training. Measure perplexity on held-out data, run task benchmarks, compare responses side-by-side with the base model, and use human preference judgments. Iterate in small loops: change the data, change one hyperparameter, measure, repeat. Error analysis should drive the next round of data or training changes.

For deeper reading, see the Hugging Face training guide, nanoGPT, and the Open LLM Leaderboard.

Ablations beat blind scaling: change one variable at a time and keep the rest of the recipe stable.

Keep iterating: small, measured changes to data and training usually beat blind scaling.
